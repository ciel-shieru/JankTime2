# ADR-0016: Keep custom-font resources consistent and reject blank production screens

- Status: Accepted
- Date: 2026-10-25

## Context

The latest screenshot artifact was 200×228 and white. CI had passed because its earlier smoke check only rejected the known mid-gray Alloy fatal dialog. Inspection found a concrete startup defect: the renderer requested Jersey10-Regular-42.fnt, but the manifest generated size 56 rather than 42. In addition, hard-coded sample metrics/rows must never appear as if they were real provider data on a user's watch.

## Options considered

1. Only check for the old mid-gray fatal dialog. This misses white-screen startup failures.
2. Keep sample values as a fallback in every normal build. This misrepresents missing data as live health/weather/alerts/tasks.
3. Keep a production build with preview disabled, compile a separate generated-JavaScript preview toggle only for CI screenshots, verify font sizes are synchronized by tests, and reject blank screenshots. This makes demo data a build-only test fixture.

## Decision

Choose option 3. The watchface uses firmware-provided Raster Gothic system fonts, so custom font resources and generated font-size manifests are intentionally absent. Unit tests enforce the supported family names and sizes. Production source exports PREVIEW_MODE=false. The CI's enable-preview script edits only the ignored generated config.js after a successful production-mode build, then rebuilds for screenshot capture. It refuses to modify an unexpected file, and preview-generated JavaScript must not be distributed.

The screenshot checker rejects either the known mid-gray fatal dialog or a blank-like image without enough dark foreground and blue/yellow accent pixels. This is a crash/blank-screen smoke test, not pixel-perfect visual approval.

## Consequences

- Any system-font family or size change in main.ts must remain within the documented firmware table and be covered by tests.
- Normal/local builds show unavailable placeholders and stale/red source icons until valid companion data arrives.
- CI screenshot artifacts show populated reference fixtures but are generated by a separate preview build.
- The screenshot must still be visually compared with the approved reference for geometry and text quality.
